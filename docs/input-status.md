# Input selector status, sync / power-on log (#139)

Firmware: branch `wb-p14ui-sync` (`/mnt/2tb/git/awto-ddc-sync`); rtdfw branch `ui-sync` (`/mnt/2tb/git/awto-rtdfw-sync`, registry row 110).
Sim test: `scripts/sync_sim.py`; selector checks in `scripts/key_sim_test.py`; host decoder `scripts/sync_log.py`, `rtd_diag.py --sync`.

## Selector (fw/sdcc/awto_osdcard.inc)
- Stays open until AUTO (take) or MENU (cancel). No SDK OSD timeout, no close by an earlier card's pending timer.
- No picture (no signal / no cable / power saving / no support): `AWTO_SRC_SLEEP_SEC` (60 s) without a key, then the SDK power-saving card (2 s) and power saving. No-signal / no-cable cards do not replace an open selector.
- A mode reset (signal lost, cable change) still closes it (SDK `UserInterfaceAdjustOsdResetProc`).
- 46 columns; per port 3 lines, fields redrawn only on change (poll every `AWTO_SRC_POLL_MS` = 250 ms):

| line | field | source |
|---|---|---|
| 1 | state: no cable / no signal / ready / ACTIVE | `ui_port_state` (SDK cable status, #60 cache) |
| 2 | signals | one row each in `fw/awto/portsig.tsv` (below) |
| 3 | sync stage | `AwtoSyncStage`: mode state + the search index's predetect / source type / judge / timing confirm (`SysInclude.h` macros); fast path pending (`g_ucAwtoFastPending`) |
| 3 | rate, active port | timing H x V, exact V freq + pixel clock (`g_stAwtoFreq`, #34), else SDK 0.1 units |
| 3 | rate, idle HDMI | `TMDS nnn.n MHz`: the port's frequency detector (P71 = D2, P72 = D3: `HDMI_FREQDET_CTRL` E6, `_OFFSET` E7, `_STABLE` EC (pop), `_RESULT_M/L` ED/EE, `_BOUND_H` F6); kHz = count x (E7[6] ? 2 : 1) x crystal / (1000 << F6[1:0]) [guess: crystal reference per regdb E6[3] = 0; check against the active port's SDK clock on unit 2] |
| 3 | rate, idle DP | `DP link HBR2 x4`: DPCD 100h / 101h = the last training (`ScalerDpGetLinkRate` / `LaneCount`); `no link` with 0 lanes or no cable |

Signals (`fw/awto/portsig.tsv`, generated by the tree's `scripts/gen_awto_sync.py`; add a row to show a new signal):
- `cable`: SDK debounced cable status. `in`: input-monitor value (`fw/awto/inputs.tsv` row; `b = 1` inverts). `cnt`: rising edges/s of an input (counted every main-loop pass). `xreg`: register + mask. `ddc`, `tmds`: below.
- D1: cbl, hpd (DPHPD), p15 / p16 (DPS15 / DPS16), p17 as edges/s (DPS17 pulses ~4 ms every 60-100 ms on unit 2, #110), ddc.
- D2 / D3: cbl, 5V (cable-detect pin H1CBL / H2CBL, low = cable per `SET_D2_CABLE_STATUS(!PCB_D2_PIN())`; [guess] it is the +5 V sense), hpd, tmds (detector has a result), ddc.
- DDC live: `DDCn_EDID_IRQ` (regdb FFE5 DDC1 / FE69 DDC2 / FE72 DDC3) bit2 SCL toggle, bit0 EDID read, write 1 = clear; bit2 is cleared only while its IRQ enable bit3 is 0 (else the SDK EXINT1 DDC wake detect owns it). Live = seen in the last 12 polls (3 s: HDCP 1.4 Ri every ~2 s x 1.25). [guess] whether DP AUX-I2C toggles the DDC1 flag.
- CEC: not shown. The regdb has no CEC register page (only `ADI_IRQ_CTRL` counting CEC and test-out fields `cec_tst_debug_p0/p1`); no board CEC pin (#101). A watcher finding becomes an `xreg` row.

## Sync / power-on log
- Ring `g_stAwtoSync` (RL6449_Project.h `StAwtoSync`, bytes only): 12 B header + 24 x 8 B entries {id, arg, ms hi, ms lo, value BE x4}; seq 0..239, entry = seq % 24. Episode = power on, input switch (selector, DDC/CI, test cmd, SDK cable switch), wake (power saving -> on, #78 held signal back), power key on.
- Entries: own events C0..CA (detect, scan done, timing, exact refresh / pixel clock, power) + the #60 switch-log events that have a row in `fw/awto/sync.tsv` (mode, panel / backlight, eDP probes, fast path, hold). Texts and value formats: `sync.tsv`, read by the firmware generator and by the host decoder; `wb_build.py` copies it beside the image (`<image>.sync.tsv`).
- Line: `+ttttt ms [Dn ]text`, ms from the episode start. Shown in the selector (last 8 lines) and on the console's event log (same decoder `AwtoSyncLine`); `rtd_diag.py BUS --sync --map MAP` prints the same lines.
- Console auto-open: once per episode, after it settles (ACTIVE / no signal / no support / power saving), only with nothing else on screen; the view scrolls to the log. Registry `sync_console` (id 110, default on). It opens after the sync, so it never delays it.

## Background scan / keep idle inputs up (#83): not built
Already there: idle receivers stay powered (`_AWTO_KEEP_IDLE_RX`, #60) and the selector reads what idle receivers have without a switch (TMDS detector, DPCD, DDC, pins). What is missing is a scan + stable check of the idle port, so the fast-switch cache could be filled. Blockers:
- Idle TMDS: the PHY / CDR set-up and `g_usTMDSRx2ClkCount` come only from the freq-stable ISR (`RL6449_Series_TMDSRx2.c` EXINT0 path, `ScalerTMDSRx2SetPhy_EXINT0` ~5.5 ms). Keep-idle disables that IRQ (`AWTO_IDLE_TMDS_OFF`: P71/P72 E6[1], EF[7]) because the ISR writes shared state (`SET_INPUT_PIXEL_CLK`, `SET_TMDS_OFFLINE_MEASURE_CLK`, colour depth) and its unstable branch forces P0_28 bit5 (display background). So `ScalerTMDSStableDetect` is FALSE on a port never scanned. Needs: the ISR body run from the main loop with EX0 masked and those globals saved / restored; then `ScalerTMDSScanInputPort` (format detect, 130 ms blind `ScalerTMDSRx2HdmiPacketDetect` D032) on the idle port.
- Idle DP: the #83 pre-fill (branch `wb-p14pf`) passes in the sim but on unit 2 the stable check failed at switch time and tries alternated "scan not DP" / "pre-detect false" (link possibly dropped by the failed scan; D1 HPD-low count 3). Root cause unknown: needs the instrumentation listed in #83 (which `ScalerDpRx1StableDetect` check fails; HPD pulses per failed scan).
- Shared state the scans write: `g_usInputPixelClk`, `g_stColorInfo` (DP Rx1 `DisplayFormatSetting`, `StreamClkRegenerate`, colorimetry; #83 comment 1); PB9_3A / PB9_38 must stay 0 while D1 is idle.
- Block time: DP scan typ 0.3-0.5 s, worst > 1 s (#60 step 4); TMDS scan up to ~180 ms + 130 ms packet detect. The watchdog bites after 5 checks without a feed (0.8-1.0 s, docs/watchdog.md): a DP scan inside one pass must be split or feed from its waits.
- Verdict: no flag-default-off implementation; nothing here is provable offline (the sim stubs `ScalerTMDSScanInputPort` / `PreDetect` / `StableDetect`, `fw_sim.video_stubs`). Next step is the #83 DP instrumentation on unit 2 (two live inputs).
