# CPU / interrupt / timer / memory conformance suite

- Purpose: clock-dependent CPU behaviour (the 350.8 MHz boot failure, docs/clock-sweep.md) shows up as a failing case with a name.
- Own build, own image: `-D _AWTO_CPU_SUITE`. `main()` = a mailbox loop; no monitor logic runs. Default image unchanged (byte-identical apart from the tag string, checked 2026-11-19).
- Source: `fw/test/cpu_suite.c` (+ `cpu_suite.h` guard-byte helper, `cpu_suite_regs.inc` generated by `scripts/cpu_suite_regs.py`). Host: `scripts/cpu_suite.py`, `./dev.py cpu-suite`.
- Databook = Synopsys DW8051 v3.2a (`/vendors/realtek/analysis/rl6449-dw8051/DW8051-databook.txt`), model `scripts/dw8051_model.json`.

## Run

- `./dev.py cpu-suite --sim --build` builds `tmp/fw/<serial>-cpusuite-{87,175,350}-be` and runs all cases in fw_sim (dw8051 core): 153 runs, 2.4 s host wall.
- One image: `./dev.py build --serial AWT26110003 --tag cpusuite-350 -D _AWTO_CPU_SUITE -D AWTO_CLOCK_MHZ=350 --fw-args="--xdata-floor 0"`.
- Filters: `--cases T_RATE0,D_XMS`, `--groups T,I,M,R,D`, `--clocks 175`. `--allow-scratch-write` enables R_WRITE (default off).
- Output: PASS / FAIL line per run + matrix; `./tmp/logs/cpu_suite.log`, `./tmp/logs/cpu_suite.tsv`.
- Unit (Phase B, test unit only, suite image flashed): `./dev.py cpu-suite --unit 3 [--clock 350] [--map F]`. Not run yet.

## What the special image keeps

- Startup: crt / XINIT, `AwtoStackPaint`, `AwtoWdtInit`, `AwtoDiagInit` / `AwtoMeasInit` / `AwtoSyncInit` (diag block, Timer2 time base behind `AwtoMs()`).
- Clock: `ScalerMcuInitial` (clock tree per `AWTO_CLOCK_MHZ`, Timer0/1/2, WDT start, debug slave 0x35 + EXINT1), `SysPowerMcuClock(M2PLL)`, `ScalerPinshareInitial`, `ScalerTimerInitialTimerEvent`, `ScalerMcuDdcRamEnable`, `AwtoDbgLinkSet(0xFF)` (debug slave on the active port's DDC; no DDC/CI here to switch it on).
- ISRs that run: Timer2 (1 ms tick `d_isr_g_usTimerCounter`, hardware WDT clear), WD warning IRQ (backstop), EXINT1 (debug slave). EXINT0 / Timer0 / Timer1: hook `AWTO_CPUS_ISR` (RL6449_Project.h) at the top of each vector function, active only while a case sets `isr_g_ucCpuIsr`.
- Not run: SysMain loop, source search, panel, display, OSD, CEC, monitor, settings, DDC/CI. They stay linked (SDCC links whole objects: no function-level drop); nothing calls them.
- Size (build 2026-11-19, 350 build): suite code ~12.6 KB in the banks (`l_CH_*` of Case* / Cpu* / AwtoCpu*; far locals), common area +3 B (0x46e3 vs 0x46e0); XDATA ~500 B (mailbox 38, buffer 320, guard 48, ISR state ~60), free XDATA 35 B vs 734 B in the default image: the suite needs `--xdata-floor 0`. IRAM: no new bytes (flags in XDATA; IRAM was full).
- Unverified until Phase B: panel pins / VDD / backlight stay at the reset + `ScalerPinshareInitial` state; debug slave reachable from the host without a source.

## Safety

- Every case is bounded (table below); long loops feed the WDT (`AWTO_WDT_PASS`); Timer2 keeps clearing the hardware watchdog. A stalled case = WDT reset = suite image restarts.
- Case frame saves / restores IE, IP, TMOD, TCON, CKCON; the SDK interrupts are off while a case runs (ET0 ET1 EX0 = 0 except the one under test).
- Never writes flash. Register tier writes only on the generated scratch list and only with `--allow-scratch-write`. DDC / I2C slave registers FF22..FF2F, EDID RAM FE60..FE6F, OSD ports, HDCP key ports: excluded (`reg_live_scan.EXCLUDE`, pages FE / FF out of the table).
- Unit 3 is returned to the default image after Phase B.

- 27 cases, 51 runs per clock (153 over 87 / 175 / 350). Groups: timers 9, interrupts 9, memory 3, registers 2, SDK helpers 4 (D_XMS 6 runs, D_POLL 3, M_PATTERN 9, R_READ 9, I_STORM 2, M_CRC 2).
- Bounds: 3 x the worst of the three sim clocks (host process backstop rule), except pure timing cases at 1.25 x the stated duration. Wall bound on the unit: 3 x bound + 2 s.
- Constants (all named in `cpu_suite.c`): rate tolerance 16 counts per window (sim instruction granularity 8), drift 32 counts per 200 ticks, latency 20 us mean (sim worst mean 11.5 us; Phase B replaces it by 1.25 x the unit's value), delay percent 98..118.
- Torn-step threshold 0x80: consecutive reads are ~10 counts apart; a torn read is off by 256.

## Findings (sim, tooling; not filed: awto-ddc is public, filing needs Dan's two checks)

- SDCC drops a volatile read that directly follows a volatile write of the same expression (warning 110 "conditional flow changed", no MOVX emitted): a "write, read back at once" test compiles to no read. Fix in the suite: the read goes through a differently spelled pointer (`CPU_RD`, asm verified). Existing write / read-back tests (`testcmd.c`, OSD SRAM tests) should be checked for the same pattern.
- I_TRIG_EX0 / I_TRIG_T0 latency in the sim scales with the flash / CPU clock ratio (counts 78 -> 138 -> 162) and is constant: those two ISRs enter through code that is never a cache hit in the sim; Timer1's ISR (23 counts at every clock) is. Databook entry time is 5..13 instruction cycles (p3-49); the rest is vector + prologue. Unit value to be measured (Phase B).
- Sim timers: Timer0 / Timer1 vs Timer2 agree to 0 counts over 200 ms (drift) but a single window differs up to 8 counts (instruction granularity). The first window after a timer start is off by ~140 counts (discarded).
- Sim does not model CKCON stretch: every M_PATTERN / R_READ stretch passes. The stretch hypothesis can only be answered on the unit.
- Sim registers are plain cells: all 33 scratch candidates store, no register is unstable.
- Sim bugs found: none that needed a sim fix (the first rate / torn / autoreload failures were test design: unprotected stopwatch reads, a poll loop slower than the timer period, flash-cache cold misses counted as torn reads; fixed in the suite).
- Not found by the suite: the 350.8 MHz boot failure does not reproduce in the sim (as before).

## Not covered (stated, not skipped silently)

- Dual DPTR (`DPS`, `DPL1` / `DPH1`) saved by every ISR: only indirectly (I_STORM copy loops use pointer increments; `--dual-dptr` code generation not forced).
- Banked code called from an ISR; register-bank / PSW / B save-restore with assembler-forced values.
- RETI "one main instruction before re-entry" (p3-49): indirectly by I_STORM progress, not single-stepped.
- Timer2 capture mode (not used by the firmware); Timer2 as baud generator.
- XDATA outside the 320 B test buffer ("whole XRAM"); IRAM / stack growth into data (stack high-water only).
- `ScalerTimerDelayXms(65535)` (65 s) and `ScalerTimerWaitForEvent` (needs scaler events).
- Real DDC / EDID RAM behaviour (read pointers advance on read).
