# Screensavers in the scaler firmware (design, Dan 2026-11-17)

Status: design only; nothing built. Prototypes today are test cmds, not screensavers.

## Decisions (Dan, 2026-11-17)

- Two screensavers, run by the scaler firmware itself (no host):
  - **Pac-Man**: `fw/test/pacman_classic.c` (+ sound `pacman_sound.c`), test cmds 0xB7 / 0xB8 / 0xB9 today.
  - **Scope**: OSD line renderer `tools/osd_lines` (384 x 216, 12 x 18 tiles, `docs/reversing/realtek-rtd/osd-font-download.md`), a waveform screen.
- **Scope 2** (Dan, 2026-11-17, reference photo of a bench scope): red graticule with minor ticks on the centre axes, green pulse trace, two dotted vertical cursors, 100 / 90 / 10 / 0 % marks on the left, readouts on top (frequency, delta t), scale labels at the bottom (volts per div, time per div). Scope 1 (`scope_saver.c`) stays as is.
  - Built 2026-11-18 (Dan: fill the screen, faster, finer). One raster 480 x 270 px = 40 x 15 tiles of 12 x 18, scaled 8x (factor 64 / 8) to the whole 3840 x 2160 panel; factor and position derive from `_PANEL_DH_WIDTH` / `_PANEL_DV_HEIGHT` (compile error when the raster does not fill the panel exactly: 1920 x 1080 gives factor 16, 2560 x 1440 gives 12). Checked in the sim at the 3840 x 2160 panel only (both 1080p60 and 2160p60 inputs scale to it).
  - Before: 28 x 9 tiles (336 x 162 px), 10.67x, 3584 x 1728 of the panel, 0.67 frames/s. Now 6.6 frames/s, trace linearly interpolated between the 64 pulse steps, graticule 8 divisions x 6 on tile-aligned lines.
  - 2-bit glyphs (MSB plane green = trace / readouts, LSB plane red = graticule / level marks). Static tiles (graticule, labels, deduped: 43) are generated by `scripts/gen_scope2.py` into `fw/test/scope2_data.inc` (upright and turned-180 copy) and uploaded once; the map points every cell at its static tile.
  - Per frame only tiles the trace, the two dotted cursors or the delta t number touch are drawn (<= 76 live + 9 per column of 205 slots, model in the generator): ring of glyph ids above the static ones, cursor-only tiles share a slot per static base, readout tiles have 8 slots of their own redrawn when the number changes. One column per step, in bands: a main pass runs <= 8 ms of saver work (+ one tile), then the main loop (DDC/CI, keys, watchdog) runs.
  - Limits: 2-bit char id = 8 bits = 256 ids (id bit 8 is a colour bit); OSD SRAM 12288 words (map 1 word per cell + 18 words per 2-bit glyph) (`docs/reversing/realtek-rtd/osd-limits.md`); fs_base 12 bit; scale-up factor 6 bit (ratio 64 / n), region size 12 bit. The ids bind, not the SRAM (4x raster 960 x 540 = 80 x 30 tiles: 67 static + 161 dynamic ids, worst case exactly full, 2.9 frames/s: `gen_scope2.py --raster 960`).
  - XDATA ~172 B (was ~30 B); const + code in banks 11 / 12 (data 5.9 KB incl. the turned copy).
  - Tools: `scripts/scope2_sim.py` (frames, fps), `scripts/scope2_ddc_latency.py` (DDC/CI reply latency, longest pass), `scripts/saver_sim.py` (fill + >= 5 frames/s + Rotate 180).
  - Mode enum gets a `Scope 2` entry; Alternate cycles all three.
- Trigger: **both** no signal and idle timeout with a live picture.
- Selection: **both** a settings-menu choice (Off / Pac-Man / Scope) and an Alternate choice (switch every few minutes).

## Hook points (to check, not yet read in detail)

- No signal: mode machine `NOSIGNAL` (`docs/design-162.md`, `docs/power-levels.md`): runs before L1 (backlight off) and L2 / L3; any L1 / L2 / L3 transition or a locking source stops it.
- Idle with picture: key / DDC activity timer (none exists), draws over the live picture, no scaler reconfiguration; any key ends it and restores the OSD state.
- Settings: registry `fw/rtdfw/settings/registry.tsv` (`scripts/settings_gen.py`), menu card `fw/osd/`.
- Pac-Man image needs ~24 KB of data across banks 11 / 12 (bank 13 is full); the scope needs its own tile map + per-frame tile uploads; check cost.
