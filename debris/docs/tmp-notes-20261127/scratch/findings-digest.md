## 4. Temperature / sensors
- Dan believes an undocumented temperature sensor exists. Findings: #206 said none (LSADC A2 + external NTC); re-open verdict: dedicated sensor UNKNOWN. RTD2525AR (RL6463, LC-tank) regdb has tsensor test signal 0x008E test_signal_sel code 0x0A and 0x410C reg_mux_nf_tsensor (N.F code from thermal sensor), page 5F thermal block in its SDK (TSENSOR_00..17, TEMP_OFFSET 0x5F53/54, TW_READ 0x5F6E/6F); not present in any 2795T-family regdb (regdbs are incomplete: 1919 SDK registers missing from ours, the 2525AR regdb lacks its own page 5F). Other Realtek families (TV SoC) have thermal sensors reading val/1024 degC and a successive-approximation one (sdata*165/128-40-7); Realtek Speed-Monitor.c DSS block comment: 'PVT: process, voltage, temperature variation' [source-code, other SoC].
- DSS ring-oscillator speed sensors in OUR regdb: 0xA750-0xA757 and 0xAF50-0xAF57 (probably the two DDR PHY channels): 0xA750-52 data_in (20-bit threshold), 0xA753 CTRL_3 {speed_en[6], data_in_ready[5], wire_sel[4] (0 long,1 short), ro_sel[3:1] (001 HVT 12T NAND, 010 multi NAND, 011 NOR, 100 multi NOR, 101 mixed, others all disabled), dss_rst_n[0] reset 1}, 0xA755-57 count_out 20-bit (delay = count/(dss_clk x 16384) for 51 elements), 0xA757[1] wsort_go, [0] ready. All dumps read zeros except CTRL_3=0x01. Unit-3 test 2026-11-19 00:26: with the final value written in ONE write (0x43 etc., ro1..3, long/short, data_in_ready) the sensor NEVER became ready within 1 s on either channel; CTRL_3 restored 0x01 OK. Realtek's own sequence is THREE writes (rst_n=0 + ro/wire set; rst_n=1; speed_en=1; poll ready) then speed_en=0/rst_n=0: retry queued. Whether dss_clk needs its own enable: unknown. Output is a delay (PVT proxy), not degrees: needs calibration.
- IOSC trim counter 0x06A4/0x06A5[7:4] as proxy: documented on all 7 regdbs; values in ISP dumps A8/C8/CB/CF/D0 (unit 1 1992, unit 3 1995/1999/2000); live 1998-2000; constant 1999 over a 30-minute soak at 350.8 MHz and 10 min stock (no visible drift at this resolution).
- ADC: regdb 0xFF08 ADC_ACONTROL (4 result regs FF09-FF0C, 5-bit [7:3], thresholds FF0F-16, ADC_CLK_DIV FF0D, wait FF17), no internal channel; Dahua firmware reads only A0/A1 (front key bands, pins 94/95) at key_scan_adc 6:3944, never A2/A3; live read FF08=B0, FF09-0C=F8 (saturated high) FF0D=04 (seen via 0x4B with MCU halted; ADC off after halt+reset otherwise).
- SDK: GET_TEMP_SENSOR_PWM = I2C command 0x71 (BeaconFactoryInclude.h:666), handler in ScalerCommonMcu.c:536 whole body `#if 0`; reply would be 7 bytes: temperature (hardcoded 0), backlight light sensor (Value2561, TSL2561-class) 2 B, target 2 B, PWM duty 2 B, checksum; live code only SET_SEND_SENSOR_DATA() (sets ucIICControl3 bit7, never read anywhere).
